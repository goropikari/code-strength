# Code Strength AI

Use this skill at the start of implementation, review, or test work when the repository defines directory-specific AI requirement levels.

## Required workflow

1. Find the repository root and `.ai-requirements.yml`.
2. Query every relevant file or directory before making a change:

   ```sh
   code-strength level --root <repo-root> <relative-or-absolute-path>
   ```

   If the installed binary is unavailable but the repository contains the CLI, use:

   ```sh
   go run ./cmd/code-strength level --root <repo-root> <path>
   ```

3. Treat the command output as one of `development`, `production`, or `unknown`.
4. For `production`, apply the repository's normal high-confidence standard: validate inputs, handle relevant failures, add focused tests, preserve observability and documentation, and consider operational behavior.
5. For `development`, implement the smallest behavior needed for local development or verification. Do not add production-grade resilience, exhaustive tests, or broad documentation unless the task requires it.
6. For `unknown`, do not silently assume production. Inspect the definition, the target's nearest configured parent, and the task context; ask the user only if the intended level remains materially ambiguous.
7. If a production directory is selected, treat all descendant directories as production too. Dependencies reached from a production starting point are also production according to the task context; the CLI does not perform dependency analysis.
8. Re-run the level query for changed paths before finalizing and report any `unknown` results.

## Path and definition rules

- Relative paths are resolved from the repository root; absolute paths are accepted.
- A file uses the level of its nearest configured parent directory.
- `.ai-requirements.yml` is regenerated by the CLI; do not hand-edit it to preserve a one-off decision.
- AI starting-point files and dependency traversal are maintained by the developer/agent separately from the YAML definition.
- `development` means the minimum implementation needed for local verification; `production` includes stronger failure handling, validation, tests, and operational documentation.

## Completion checks

- Confirm the selected level before implementation.
- Keep the implementation proportional to that level.
- Run the relevant tests and linters.
- Confirm no changed path unexpectedly resolves to `unknown`.
