# ディレクトリ別AI要求レベルガイド

## 1. タイトル

ディレクトリ別AI要求レベルガイド

## 2. 要約

開発環境専用のコードに対しても、AIエージェントが本番環境向けの過剰な品質・堅牢性を適用してしまう問題を解決する。

Go・Cobra製のCLIツールでリポジトリ内のディレクトリを列挙し、検索可能なターミナルUIからproduction対象を選択する。選択結果から、全対象ディレクトリの要求レベルを記述したYAMLファイルを再生成する。要求レベル定義ファイルとは別に、AIがproduction扱いを開始する起点ファイルを開発者が管理する。AIエージェントは起点から依存関係を再帰的に辿り、到達したコードもproductionとして扱う。

## 3. 課題

- 開発環境だけで使うコードにも、本番レベルの過剰な実装が行われる。
- 過剰な実装により、コード量・設計の複雑さ・レビュー負荷が増える。
- AIがディレクトリの用途や期待される要求レベルを把握できない。
- 要求レベルを毎回プロンプトで説明する必要があり、開発者の認知負荷が高い。

## 4. 目的

- AIエージェントが対象ディレクトリの要求レベルを実装開始時に把握できるようにする。
- 用途に見合った要求レベルで実装させ、不要な本番向け実装を減らす。
- リポジトリ全体の要求レベルを一元的に管理できるようにする。

## 5. 非対象

- AIが生成したコードを自動的に本番投入可能か判定すること。
- 要求レベルに適合しているかを自動検査・自動修正すること。
- AI向け起点ファイルをCLIが生成・更新すること。
- ディレクトリごとの設定ファイルを配置・管理すること。
- 特定のAIモデルや特定の実装言語に依存した品質判定を行うこと。

## 6. 対象ユーザー

AIエージェントに実装作業を依頼する開発者。開発者はCLIで要求レベル定義を生成し、AI向け起点ファイルを手動で管理する。AIエージェントは両方の情報を参照して実装方針を決める。

## 7. スコープ

### 初版に含めるもの

- Go 1.26で実装するCLIツールの提供。
- CLIフレームワークとしてCobraを使用する。
- `development` と `production` の2段階の要求レベル。
- リポジトリ内のディレクトリを全列挙する機能。
- 検索可能なターミナル上の対話型UIで、production対象を複数選択する機能。
- `.git`、`node_modules` などの標準除外を初期適用し、除外対象を追加・変更する機能。
- `directories` 配列に全対象ディレクトリを列挙し、各ディレクトリの要求レベルを記録するYAMLファイルの生成。
- `exclude` 配列に対象外パスを記録するYAMLファイルの生成。
- 既存の要求レベル定義ファイルを引き継がず、全量を再生成する動作。
- AI向け起点ファイルを要求レベル定義ファイルとは別に管理する前提。
- AIがAI向け起点から依存関係を再帰的に辿り、到達したコードをproductionとして扱う前提。

### 将来候補

- 要求レベルと実装内容の適合検査。
- 要求レベルの判断理由や適用結果のログ。
- AI向け起点ファイルの生成支援。

## 8. ユーザーフロー

1. 開発者がproductionとして扱いたいディレクトリの候補をCLIに渡す、またはCLIを起動する。
2. CLIがリポジトリ内のディレクトリを全列挙する。
3. CLIが標準除外を適用する。
4. 開発者がターミナルUIでパスを検索し、production対象を複数選択する。
5. 開発者が必要に応じて除外対象を追加・変更し、確定する。
6. CLIが要求レベル定義YAMLを全量再生成する。
7. 開発者がAI向け起点ファイルを別途作成・管理する。
8. AIエージェントが実装開始時に要求レベル定義とAI向け起点を参照する。
9. AIエージェントが起点から依存関係を再帰的に辿り、実装・テスト・エラーハンドリング・ドキュメントの範囲を決定する。
10. 開発者が生成されたコードをレビューし、不要な本番向け実装が減っているか確認する。

## 9. 機能要件

### 9.1 CLI

- Go 1.26で実装すること。
- CobraをCLIフレームワークとして使用すること。
- リポジトリルートと出力先を指定できること。
- 対話型選択を使わない自動実行が必要になった場合に拡張できる構造であること。

### 9.2 ディレクトリ選択

- リポジトリ内のディレクトリを全列挙すること。
- `.git`、`node_modules` などを標準で除外すること。
- 除外対象を追加・変更できること。
- パスを検索して候補を絞り込めること。
- 複数のディレクトリを選択できること。
- 選択を確定して要求レベルを生成できること。

### 9.3 要求レベル定義YAML

- YAML形式であること。
- `directories` 配列に対象ディレクトリをすべて列挙すること。
- 各要素が `path` と `level` を持つこと。
- `level` は `development` または `production` のいずれかであること。
- `exclude` 配列に対象外パスをまとめて記述すること。
- 生成形式は次の例に従うこと。

```yaml
directories:
  - path: .
    level: development
  - path: docker/production
    level: production
  - path: services/api
    level: production

exclude:
  - .git
  - node_modules
```

- 既存ファイルがある場合も、既存内容を保持せず全ディレクトリ分を再生成すること。

### 9.4 AI向け起点と依存関係

- AI向け起点ファイルは要求レベル定義YAMLと別ファイルであること。
- AI向け起点ファイルは開発者が手動で作成・管理すること。
- AIエージェントが実装開始時にAI向け起点を参照できること。
- AIエージェントが起点から依存関係を再帰的に辿れること。
- production起点から到達したコードをproductionとして扱えること。
- 依存関係の解析・判断はAIに行わせ、初版のCLIに静的解析機能を要求しないこと。

### 9.5 AIへの提示

- AIエージェントが要求レベルを作業コンテキストとして参照できること。
- 要求レベルが、実装の過剰化を抑制する明確な指示として提示されること。
- AIが要求レベルに応じて、テスト、エラーハンドリング、ドキュメントなどの実装範囲を調整できること。

## 10. 制約と依存関係

- 要求レベル定義はリポジトリルートの単一YAMLファイルを正とする。
- AI向け起点ファイルは要求レベル定義ファイルとは別に管理する。
- 設定内容は人間にもレビュー可能で、バージョン管理できる形式である必要がある。
- AIエージェントが実装開始時に対象ディレクトリを識別できる必要がある。
- CLIは要求レベル定義のみを生成し、AI向け起点ファイルを変更しない。
- 本PRDではAIエージェントとの具体的な連携方式は規定しない。

## 11. 成功指標

主指標は、AIが生成したコードのレビューにおいて、開発環境専用コードへの不要な本番向け実装が減少したと開発者が判断できることである。

導入前後の同種タスクを比較し、以下をレビューする。

- 開発環境専用コードに不要なエラーハンドリングが追加されていないか。
- 不要に広範なテストやドキュメントが追加されていないか。
- 要求レベルに対して実装の複雑さが妥当か。

## 12. リスクと例外

- 要求レベルの意味が曖昧だと、AIの判断が安定しない。
- 設定の対象パスを誤ると、意図しない要求レベルが適用される。
- AIが依存関係を誤って辿ると、production対象の漏れや過剰適用が発生する。
- AIが要求レベルを無視した場合、初版では自動検知できない。
- リポジトリが大きい場合、全ディレクトリ列挙や検索性能が問題になる。
- 全量再生成により、手動編集した要求レベルが失われる可能性がある。

## 13. リリース計画

1. YAMLの要求レベル定義形式とファイル名を決定する。
2. Go 1.26・Cobra製CLIの基本コマンドを実装する。
3. ディレクトリ列挙、標準除外、検索、複数選択を備えたターミナルUIを実装する。
4. 全対象ディレクトリの要求レベル定義YAML再生成を実装する。
5. 代表的なリポジトリ構成で生成結果を検証する。
6. AI向け起点からの依存関係の再帰的な判断をAIエージェント側で検証する。
7. 開発環境専用コードを対象に試行し、コードレビューで効果を確認する。

## 14. 未解決事項

- CLIのコマンド名・サブコマンド名。
- 要求レベル定義YAMLのファイル名・配置。
- AI向け起点ファイルのファイル名・形式・配置。
- CLIにproduction対象の候補を渡す方法と、対話型UIとの役割分担。
- 標準除外の具体的な一覧。
- 除外対象をUIで追加・変更する具体的な操作方法。
- AIが依存関係を辿る際の対象範囲と停止条件。
- YAMLの構文エラーや不正な要求レベルを検出した場合の動作。
- 要求レベルを無視した実装を将来どのように検出するか。

## 15. 前提

- AIエージェントは実装対象のディレクトリを特定できる。
- AIエージェントは実装開始時に要求レベル定義とAI向け起点を取得できる。
- production起点から依存関係を辿る作業はAIが担う。
- 要求レベルは、コードの安全性だけでなく、テスト・エラーハンドリング・ドキュメントの範囲も含む概念として扱う。
- 初版では、要求レベルを提示することでAIの実装判断を誘導することを目的とする。
- 本PRDでは、AIエージェントやAI製品固有の実装方式は規定しない。

## 16. 付録

### 要求レベルの意味

| 要求レベル    | 意図                                                                 |
| ------------- | -------------------------------------------------------------------- |
| `development` | 動作確認に必要な最小限の実装。過剰な堅牢性や網羅的なテストは求めない |
| `production`  | 障害対応、入力検証、テスト、運用を含む高い要求レベル                 |

要求レベルはこの2種類に固定する。productionとして扱う依存先は、AI向け起点からAIが再帰的に判断する。
